# خطة: توليد أصوات حوارية (صوتان أو ثلاثة) لنصوص فيديوهات نبضة

> ملف مخصّص لإعطائه لـ Antigravity لتنفيذه داخل مشروع `C:\nabda_app`.

## 1. الهدف

أداة صغيرة (سكربت Python) تأخذ نص فيديو مكتوباً كحوار بين 2 أو 3 شخصيات، وتولّد ملف صوت واحد للحوار كاملاً بأصوات مختلفة، عبر ElevenLabs **Text to Dialogue API**، ثم توحّد مستوى الصوت ليكون جاهزاً للمونتاج.

## 2. الأداة المستعملة

- Endpoint: `POST https://api.elevenlabs.io/v1/text-to-dialogue`
- الجسم: `inputs` = قائمة من `{ "text": "...", "voice_id": "..." }` بترتيب الحوار، و`model_id` (الافتراضي `eleven_v3`).
- حدود مهمة:
  - 10 أصوات مختلفة كحد أقصى في الطلب الواحد.
  - مجموع النصوص في الطلب الواحد ≤ 2000 حرف تقريباً للحصول على نتيجة مستقرة.
- وسوم النبرة مدعومة داخل النص: `[excited]`، `[warmly]`، `[laughs]`، `[whispers]`، `[sighs]`...
- اجعل `model_id` قابلاً للتغيير في الإعدادات (جرّب `eleven_v3`، ثم Eleven v4 إن كان مدعوماً في هذا الـ endpoint على حسابك).

## 3. الأصوات (الشخصيات)

| المفتاح | الشخصية | voice_id |
|---|---|---|
| `amina` | أمينة، الأم/الراوية (صوت السوفية) | `EOqeBn9r5h39ZDHmwXGa` |
| `sara` | صديقتها / أخت (أنثى ثانية بنبرة مختلفة) | **يُحدَّد لاحقاً** من مكتبة أصوات ElevenLabs |
| `karim` | الزوج (صوت رجالي) | **يُحدَّد لاحقاً** |

- لا تخترع `voice_id`: الأداة تقرأ الأصوات من `voices.json`، وتتوقف برسالة واضحة إن كان أحدها فارغاً.
- أضِف أمراً مساعداً `list-voices` يعرض الأصوات المتاحة في الحساب (`GET /v1/voices`) لاختيار الصوتين الآخرين.

## 4. صيغة ملف النص

ملف لكل فيديو في `brand_nabda/dialogues/scripts/`، مثلاً `d01_asmaa.txt`:

```
# title: واش نسمّيه؟
# speakers: amina, karim
karim: [curious] ولد ولّا بنت؟ والسؤال الأصعب... واش نسمّيه؟
amina: [laughs] ما تخافش! في نبضة كاين أكثر من ألف وسبع مية اسم، وكل اسم بمعناه.
karim: [surprised] بصّح؟ وريني!
amina: [warmly] شوف... «يوسف»: يزيد الله ويبارك في العطاء.
karim: [excited] هذا هو! نبضة دوت أونلاين!
```

- سطر لكل دور: `المفتاح: النص`.
- الأسطر التي تبدأ بـ `#` بيانات وصفية تُتجاهل في التوليد.

## 5. منطق التنفيذ

1. **قراءة وتحقق:** قراءة الملف، والتأكد أن كل متحدث موجود في `voices.json`، وأن عدد المتحدثين بين 2 و3.
2. **التقسيم:** إذا تجاوز مجموع الحروف 2000، يُقسَّم الحوار إلى دفعات عند حدود الأدوار (لا يُقطع دور في منتصفه).
3. **التوليد:** طلب `text-to-dialogue` لكل دفعة، مع حفظ الاستجابة كـ `mp3`.
4. **الدمج:** دمج الدفعات بـ ffmpeg مع فاصل 0.25 ثانية بينها.
5. **توحيد المستوى:** نسخة `_norm.mp3` عند −14 LUFS باستعمال `loudnorm` (المعيار المناسب لتيك توك وإنستغرام).
6. **التوقيت (اختياري):** ملف `.srt` للترجمة عبر Speech-to-Text (ElevenLabs أو faster-whisper محلياً)، لتسهيل وضع الكتابة على الفيديو.
7. **وضع التجربة `--dry-run`:** يطبع عدد الحروف لكل فيديو ومجموعها، دون أي طلب مدفوع.

## 6. هيكل الملفات

```
brand_nabda/dialogues/
  voices.json            # المفاتيح → voice_id
  scripts/*.txt          # النصوص
  out/<name>.mp3         # الصوت الخام
  out/<name>_norm.mp3    # الصوت الموحّد للمونتاج
  out/<name>.srt         # الترجمة (اختياري)
tools/dialogue_tts.py    # السكربت
.env                     # ELEVENLABS_API_KEY (لا يُرفع إلى git)
```

أوامر الاستعمال:

```
python tools/dialogue_tts.py list-voices
python tools/dialogue_tts.py build brand_nabda/dialogues/scripts/d01_asmaa.txt --dry-run
python tools/dialogue_tts.py build brand_nabda/dialogues/scripts/d01_asmaa.txt
python tools/dialogue_tts.py build-all
```

## 7. قواعد إلزامية

- **مفتاح API:** في `.env` فقط. يُضاف `.env` و`brand_nabda/dialogues/out/` إلى `.gitignore`. لا يوضع المفتاح أبداً داخل كود Flutter أو أي ملف يُرفع إلى git.
- **المحتوى** (التزام بسياسات Google Play وتعليمات `CLAUDE.md`):
  - لا ادعاءات طبية ولا نصائح علاجية، ولا ذكر لأطباء أو «فريق طبي».
  - لا مكملات غذائية ولا أجهزة طبية.
  - لا ميزات مخفية حالياً: التطعيمات، عدّاد الركلات، الأدوية، الضغط، المساعد الذكي.
- **اللغة:** دارجة جزائرية طبيعية. الأرقام تُكتب بالحروف («ألف وسبع مية») لتُنطق صحيحة.
- **التنفيذ التدريجي:** جرّب فيديو واحداً أولاً، واستمع إليه، ثم شغّل `build-all`.

## 8. معايير القبول

- فيديو تجريبي واحد بحوار بين صوتين، يُسمع فيه تبدّل الأصوات بوضوح، بلا قطع داخل الجمل.
- الوسوم مثل `[laughs]` لا تُنطق ككلمات.
- `_norm.mp3` قرب −14 LUFS (يُتحقّق بـ `ffmpeg -af ebur128`).
- `--dry-run` لا يرسل أي طلب.
- لا يظهر المفتاح في أي ملف داخل git (`git grep -n "sk_"` يرجع فارغاً).
